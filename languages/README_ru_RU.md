# RotatedWorldZ

Версия RotatedWorld на 20 языках (плагин для Paper/Folia, поворачивающий весь мир на 90° вокруг оси X для игрока с помощью PacketEvents):
Скомпилированы **Java, Kotlin, Scala 3, Gosu, Groovy, Kawa Scheme, Xtend, Fantom, Flix, Frege, Clojure, Haxe**,
плюс 8 скриптовых слоёв, загружаемых во время выполнения: **Kotlin Script, JRuby, JavaScript, Jython, Lua, BeanShell, Common Lisp, Prolog** — всё собрано в **один JAR-файл**.


## Кто за что отвечает

| Слой | Язык | За что отвечает | Почему именно он |
|---|---|---|---|
| 0 api | Java | Контракты для реализации слоем чистых вычислений (только типы JDK) | Наименьший общий знаменатель, понятный всем компиляторам |
| 1 Чистые вычисления | **Frege** | Алгебра координат: единственное определение вращения плюс 10 свойств QuickCheck | Чистые функции + встроенный QuickCheck; компилируется в методы `static int/float/double` без боксинга |
| | **Flix** | Правила именования блоков (напольный ↔ настенный, типы block entity); очистка кэша | Таблицы правил + система эффектов гарантируют чистоту; «какие чанки ещё кому-то нужны» — правило **Datalog** |
| | **Clojure** | Парсинг конфигурации: параметры описаны как данные схемы | Data-driven подход: добавить параметр = добавить строку данных |
| | **Haxe** | Вращение массивов полубайтов (nibble) освещения | Использует только `haxe.io.Bytes`, один и тот же код компилируется в JS/C++ (например, для оффлайн-просмотрщика) |
| | **Fantom** | Стратегия поиска безопасной точки опоры | Чистый алгоритм, смотрит на мир через интерфейс `BlockProbe`, не касается Bukkit |
| 2 kernel | Java | Состояние игрока `PlayerState`, `SerialExecutor`, интерфейсы `Host` / `BlockRotator` | Конкурентное разделяемое состояние с volatile / атомарными переменными, на Java пишется наиболее прямо |
| 3 Движок | **Scala 3** | Кэш чанков `ChunkStore` + движок поля зрения `ViewManager` (плавающий центр координат, предвыборка, отправка чанков) | Ядро производительности, массивная обработка циклов по массивам |
| | **Gosu** | `WorldProbe`: проверки блоков / хитбоксов Bukkit; enhancements для `Material` | Enhancements добавляют свойства типам Bukkit (`type.Hazard`) |
| | **Groovy** | Оркестрация выполнения команды `/rotate` | Холодный путь (Cold Path) |
| | **Kawa Scheme** | Очистка кэша: собирает радиус обзора каждого мира и передаёт в Datalog во Flix для решения, что оставить (ранее в Scala `ViewManager`) | Опережающая компиляция (AOT), обработка списков |
| | **Xtend** | `BlockRotation`: правила вращения BlockData | Автоматическое приведение типов при `instanceof` + синтаксис свойств; правила читаются как сама спецификация |
| 4 Плагин | **Kotlin** | Переписывание пакетов (горячий путь Netty), события Bukkit, фасад векторов PacketEvents | Исходный код; синтаксис PacketEvents на Kotlin наиболее лаконичен |
| | Java | Точка входа плагина (реализует `Host`), мост запуска Flix/Fantom/Clojure, загрузчик скриптовых слоёв | Вход и сборка компонентов |
| 5 Скрипты | **Kotlin Script** | Решение о репозиционировании плавающего центра координат (ранее в Scala `ViewManager`) | Во время выполнения компилируется в байт-код, вызов каждый тик не вызывает просадок |
| | **JRuby** | Порядок отправки столбцов чанков (ранее в Scala `ViewManager`) | Цепочка `product.each_with_index.sort_by` |
| | **JavaScript** | Пропуск лагов при «слишком быстром перемещении» (ранее в слушателе Kotlin) | Интерпретируется Rhino, редкие события |
| | **Jython** | Отбрасывание (Knockback; ранее в слушателе Kotlin) | Вызывается один раз при каждом получении урона |
| | **Lua** | Урон от падения (ранее в слушателе Kotlin) | Главный присяжный |
| | **BeanShell** | Строка текста для `/rotate status` (ранее в Groovy) | Скрипт с синтаксисом Java |
| | **Common Lisp** | Какие серверные проверки пропускать для повёрнутых игроков (неудачное движение, кик за полёт) (ранее в слушателе Kotlin) | Таблица решений `cond` |
| | **Prolog** | Синтаксис аргументов `/rotate`, описанный через DCG (ранее в Groovy) | Грамматику следует описывать с помощью DCG |
| | **Все восемь + Kawa** | **Жюри присяжных по урону от падения**: Девять языков вычисляют независимо, решение большинством голосов, при равенстве решает Lua, при разногласиях пишется предупреждение | Развлечение |

**Слой 1 на уровне сборки вообще не видит Bukkit и PacketEvents** (ему доступен только `api`), а пять языков внутри него также изолированы друг от друга. Вызовы вниз — это обычные вызовы JVM; вызовы вверх возможны только через интерфейсы: Flix и Fantom передают реализации в `api.Services`, а главный класс плагина предоставляет сервисы третьему слою через `kernel.Host`.

## Скриптовый слой

Скрипты не компилируются в JAR, а загружаются встроенными интерпретаторами при запуске плагина (`script.ScriptLayers`, 8 интерпретаторов запускаются параллельно примерно за 4–5 секунд):

* Исходный код находится в `src/main/<kts|jruby|javascript|jython|lua|beanshell|commonlisp|prolog>/rules.*` и при сборке упаковывается в папку `scripts/` внутри JAR.
* Если файл `plugins/RotatedWorldZ/scripts/<папка>/rules.*` существует, он перезаписывает версию из JAR: **чтобы изменить правила, не нужно пересобирать проект — достаточно перезапустить сервер**.
* Интерфейсы, реализуемые скриптами, находятся в `api.ScriptedRules`. Последним выражением в Kotlin Script должен быть объект, одновременно реализующий `Recenter` и `FallJuror`, причём не анонимный; остальные скрипты определяют только глобальные функции (в Prolog — предикаты, где последний аргумент является результатом), которые Java оборачивает в интерфейсы.
* Встроенные интерпретаторы не гарантируют потокобезопасность; вызовы каждого скрипта синхронизированы (`synchronized`). Поэтому только Kotlin Script (выполняется скомпилированным) находится на горячем пути каждого тика, остальные — на холодном пути.
* Поставляемые с Jython библиотеки jnr/jffi конфликтуют по версиям с JRuby, поэтому при сборке Jython упаковывается отдельно с релокацией этих пакетов (задача `jythonIsolated`, по аналогии с апстрим-шаблоном).

Места, где гарантируется согласованность между языками:

* Сопоставление сторон блоков (UP→NORTH…) больше не пишется вручную: Xtend (Bukkit `BlockFace`) и Kotlin (PacketEvents `BlockFace`) выводятся из одного и того же поворота во Frege.
* Отображение координат внутри секции `Geometry.localIndex` (Frege) и поворот освещения Haxe используют абсолютно одинаковое преобразование; `smokeTest` выполняет поблочное сравнение.

## Сборка

```bash
./gradlew build          # Артефакт: build/libs/RotatedWorldZ-1.0.0.jar; включает checkGeometry и smokeTest
./gradlew checkGeometry  # Запуск только свойств QuickCheck во Frege
./gradlew smokeTest      # Сервер не требуется: запускает слой чистых вычислений из готового JAR, сравнивает с исходным поведением Kotlin и проверяет линковку остальных слоёв
```

Для работы на сервере требуется установленный PacketEvents (`depend: [packetevents]`).

При первой сборке Flix, Haxe и Fantom будут загружены в `.tools/` (~60 МБ); Haxe дополнительно требует JDK 8 (только ради его `rt.jar`; если Gradle toolchain его не найдёт, он автоматически скачается через Foojay). Для всего остального используется JDK 21.

## Подводные камни разных языков

* **Flix**: Может экспортировать только одну входную функцию, генерируемую в классе `Main` дефолтного пакета (`FlixBridge` вызывает её через рефлексию). Он также генерирует в корне около 500 классов и пакетов (`Array`, `List`…), которые перекрыли бы собственные `Array`/`List` в Scala/Kotlin; поэтому выходные файлы Flix **не входят ни в один classpath компиляции**, а попадают только в runtime и JAR. Guard-условия в Datalog захватывают максимум 5 переменных. Интерфейсы Java и модули Flix не могут иметь одинаковые имена.
* **Frege**: Параметры по умолчанию ленивые (в сигнатурах Java представлены как `Lazy<Float>`); чтобы потребовать строгие примитивные типы, перед паттерном нужно поставить `!`.
* **Fantom**: Реализация интерфейсов Java с default-методами приводит к сбою, поэтому интерфейсы в `api` не содержат default-методов. Типы Java `long`/`double`/`boolean` напрямую соответствуют `Int`/`Float`/`Bool` в Fantom, а все ссылочные типы являются nullable. Литералы с плавающей точкой нужно писать как `0.5f` (`0.5` — это Decimal).
* **Gosu**: `block` является ключевым словом (лямбда в Gosu). gosuc сразу же резолвит типы аннотаций, поэтому в classpath компиляции должны присутствовать зависимости Paper API `org.jetbrains:annotations` и `jspecify`.
* **Xtend**: Bukkit `Keyed` содержит одновременно `key()` и `getKey()`; выражение `b.key` неоднозначно, поэтому нужно писать `b.getKey`. Если поле и метод имеют одинаковое имя, обращение внутри тела метода указывает на метод.
* **Haxe**: Целевая платформа `--jvm`; внешний загрузчик классов Java распознаёт только `rt.jar` от JDK 8; `haxelib` в официальном дистрибутиве для Windows зависит от Neko, поэтому при сборке в PATH подставляется заглушка.
* **Clojure**: Полагается на контекстный загрузчик классов потока (Thread Context ClassLoader) для поиска пространств имён; `ClojureBridge` временно переключает его на загрузчик классов плагина во время инициализации и вызовов.
* **Kotlin Script**: Результат скрипта не может быть анонимным объектом (`object : X {}` выдаёт ошибку "anonymous type"); необходимо предварительно объявить именованный класс.
* **Kawa**: Java `null` в Scheme является истинным значением (только `#f` ложно); проверка пишется как `(eq? x #!null)`; чтение полей — `obj:field`, вызов методов — `(obj:method)`.
* **Контекстный загрузчик классов потока**: Контекстный загрузчик потоков сервера (главный поток, потоки регионов, Netty, глобальный планировщик) не видит классы плагина, тогда как среды выполнения Kawa и Clojure ищут классы по имени именно через него. Поэтому любые вызовы из потоков сервера в эти среды выполнения оборачиваются в `kernel.PluginContext` (очистка кэша Kawa, жюри, вызовы скриптов, поиск точек опоры Gosu/Fantom, команды Groovy). По этой причине главный поток `smokeTest` устанавливает контекстным загрузчиком platform classloader, имитируя потоки сервера.
* **Prolog**: tuProlog по умолчанию не загружает DCG; для доступности `-->` и `phrase/2` необходимо вызвать `loadLibrary(new DCGLibrary())`.
* **Jython**: `PyString` — это байтовая строка Python 2; при наличии не-ASCII символов (например, китайских иероглифов) в пути нужно использовать `Py.newStringOrUnicode`. Поэтому `smokeTest` запускается из не-ASCII пути вроде `build/smoke/插件 plugins/`.
* **Common Lisp (ABCL)**: При инициализации пытается через рефлексию открыть фабрику виртуальных потоков JDK; без параметра `--add-opens java.base/java.lang` он выводит строку в `System.err` (из-за чего Paper выдаёт предупреждение «плагин использовал System.err»). Это безвредно; `StderrFilter` перехватывает ровно эту строку во время инициализации ABCL.
* **Жюри присяжных**: `ceil(2.5 - 3)` даёт `-0.0`, и функция `max` в Python / Kotlin / Scheme сохраняет его как есть; перед подсчётом голосов его необходимо нормализовать в `0.0`, иначе при падении на 2–3 блока ошибочно фиксируется «разногласие».
* **Gosu**: Сразу после инициализации среды выполнения открывает `java.base` для рефлексии, после чего проблемы с рефлексией в других библиотеках становятся незаметными. Поэтому `smokeTest` соблюдает порядок `onEnable` плагина: сначала загружает скриптовые слои, и лишь затем инициализирует Gosu. Параметр `./gradlew smokeTest -PsmokeJava=25` позволяет запускать тесты на той же версии JDK, что и сервер.
* **JRuby**: Метод `sort_by` нестабилен; чтобы сохранить исходный порядок, индекс необходимо включать в ключ сортировки.
* **Scala 3**: После удаления исходных файлов инкрементальная компиляция может оставлять устаревшие файлы `.tasty`, попадающие в кэш сборки. Если в JAR обнаружены лишние классы, выполните `./gradlew clean build --rerun-tasks`.

## Проверено / Не проверено

Проверено (Windows 11, JDK 21, Gradle 9.7.1):

* Все 12 компилируемых языков успешно компилируются, все 8 скриптовых слоёв успешно загружаются, `./gradlew clean build --rerun-tasks` проходит без ошибок.
* `checkGeometry`: 10 свойств QuickCheck пройдены, включая обратимость (roundtrip), согласованность сетка/точка, соответствие поворота угла обзора и вектора, `zBase` как целочисленное деление с округлением вниз.
* `smokeTest` (всего 123 134 проверки, запуск в изолированном загрузчике классов из пути с китайскими символами для имитации загрузки плагина; протестировано на JDK 21 и 25):
  * Результаты правил Flix, конфигурации Clojure, освещения Haxe и поиска Fantom по всем пунктам совпадают с исходной реализацией на Kotlin;
  * Результаты 8 скриптов и Kawa по всем пунктам совпадают с замещённым ими исходным кодом, все девять голосов жюри единогласны без предупреждений; при загрузке скриптовых слоёв вывод в `System.err` отсутствует;
  * Слои Scala/Gosu/Groovy/Xtend/Kotlin успешно линкуются, среды выполнения Gosu/Groovy/Scala корректно инициализируются.

**Не проверено**:

* Не тестировалось на реальном сервере Paper / Folia и не проверялось подключение игрового клиента (для этого требуется принять Minecraft EULA и установить PacketEvents). Зависящие от сервера пути (переписывание пакетов, отправка чанков, репозиционирование) гарантируются только проверками компиляции и «построчным переносом оригинала». Перед использованием в продакшене протестируйте на тестовом сервере.
* Размер JAR около 231 МБ (оригинал — 4.9 МБ): компилятор Kotlin, JRuby, Jython, ABCL, плюс рантаймы Gosu, Groovy, Scala, Clojure, Frege и Kawa. Запуск плагина занимает на 4–5 секунд дольше из-за загрузки скриптовых слоёв. Эти среды выполнения упакованы как есть, без релокации: если на том же сервере другой плагин использует иные версии Kotlin/Scala/Groovy, возможны конфликты.

## Структура каталогов

```
src/api/java        Слой 0: контракты слоя чистых вычислений (типы JDK)
src/kernel/java     Слой 2: разделяемое состояние и сервисные интерфейсы (Bukkit + PacketEvents)
src/main/<язык>     Исходный код на каждом из языков (скриптовые слои в src/main/{kts,jruby,javascript,jython,lua,beanshell,commonlisp,prolog})
src/main/resources  plugin.yml, config.yml
buildSrc            Задачи сборки Gradle для каждого языка
build.gradle.kts    Слои и зависимости
```
